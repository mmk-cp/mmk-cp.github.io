Agentic AI project2026

AI Agent for Blog Content Production

Multi-step AI agent for blog content production built with Python, OpenAI, LangChain, and LangGraph. The workflow is stateful, letting a human approve or edit outputs at review gates, add instructions, and resume execution from the same state.

User Input→LangGraph Agent→LLM (OpenAI)→Tool / Stage→Human Review→Result
  • Orchestrated independent content-production stages and managed workflow state with LangGraph.
  • Implemented human-in-the-loop controls for pausing, reviewing, revising, and resuming the process in a controlled way.
Engineering case study
Problem

Blog content production spans several dependent stages, and each stage output needs review before continuing; without human oversight, an early-stage error would invalidate the entire chain.

Architecture / Approach

Each stage was implemented as an independent node in a LangGraph graph, with full workflow state persisted. At review gates execution pauses and resumes from the same state after the user approves or edits.

Engineering decisions

LangGraph was chosen for orchestration and state management to keep resumable execution and stage branching simple; LangChain abstracts LLM invocation.

Agentic AI project2025

AI Agent for Address Validation & Geolocation

Intelligent address-processing system for order registration that validates city and province existence, verifies city-province membership, and normalizes address structure. After the LLM evaluates the address text, the agent uses tool calling to send it to the Neshan API, retrieve candidate coordinates, reverse-geocode them, and compare the returned address with the input. Precise coordinates are stored only above a similarity threshold; otherwise city reference coordinates are used.

Address Input→LLM Evaluation→Tool: Neshan Search→Reverse Geocode→Similarity Check→Store / Fallback
  • Designed a validation and normalization pipeline for incomplete or inconsistent city, province, and address data.
  • Integrated LLM tool calling with the Neshan API and implemented similarity-threshold decisions with a reliable fallback.
Engineering case study
Problem

At order time, addresses are often incomplete or inconsistent, and incorrect geocoding can disrupt logistics.

Architecture / Approach

The agent first evaluates the address text with an LLM, then retrieves candidate coordinates via tool calling to the Neshan API and verifies them with reverse geocoding.

Engineering decisions

The final decision uses a similarity threshold between the input address and the reverse-geocoded result; below threshold the city reference coordinates are stored as a fallback to avoid persisting incorrect coordinates.
